## Project Overview

MediCost AI is a data-driven web application that uses a trained **Gradient Boosting Regressor** to estimate a person's annual medical insurance charges. Users enter six health and demographic inputs through a clean, professional form. The prediction is generated in real time by the Flask backend using the saved scikit-learn pipeline and displayed in an interactive result card that includes a risk category, annual estimate, and monthly breakdown.

The application also includes a live analytics dashboard populated entirely from the real insurance dataset, and a model performance section that displays MAE, RMSE, R², and feature importance directly from the backend API.

---

## Problem Statement

Healthcare costs vary significantly across individuals and are influenced by a combination of demographic, lifestyle, and geographic factors. Without a reliable cost estimation tool, individuals and insurers struggle to anticipate annual medical expenditure, leading to under-insured populations and financial uncertainty.

This project addresses that gap by building a machine learning model trained on real US medical insurance data that can accurately predict annual healthcare charges given a patient's age, BMI, smoking status, region, sex, and number of dependants.

---

## Objectives

- Analyse the US Medical Insurance Costs dataset to identify key cost drivers.
- Preprocess the data with a reproducible, leakage-free scikit-learn pipeline.
- Train and compare five regression algorithms on identical train/test splits.
- Select the best-performing model based on test R², MAE, and RMSE.
- Persist the complete preprocessing and model pipeline to disk.
- Expose the model through a REST API built with Python Flask.
- Build a responsive, professional web frontend that connects to the API and displays real predictions and live analytics.

## Data Preprocessing

The preprocessing pipeline is built using scikit-learn's `ColumnTransformer` and serialised together with the trained model into a single `.pkl` file. This guarantees that prediction inputs are transformed with **exactly** the same fitted transformers used during training — no manual re-encoding at inference time.

### Steps

1. **Duplicate removal** — the one duplicate row is dropped before any split (`drop_duplicates()`).
2. **Train/test split** — 80 % training (1,069 records) / 20 % test (268 records), `random_state=42` for reproducibility.
3. **Numerical features** (`age`, `bmi`, `children`) — standardised with `StandardScaler` (zero mean, unit variance). Helps linear models converge; tree-based models are scale-invariant but the scaler is retained for pipeline consistency.
4. **Categorical features** (`sex`, `smoker`, `region`) — encoded with `OrdinalEncoder` using fixed, deterministic category lists:
   - `sex`: `[female, male]`
   - `smoker`: `[no, yes]`
   - `region`: `[northeast, northwest, southeast, southwest]`
   - `handle_unknown="use_encoded_value"` with `unknown_value=-1` ensures graceful handling of unseen categories.

## Machine Learning Methodology

### Pipeline Architecture

```
Input Dict (age, sex, bmi, children, smoker, region)
        │
        ▼
ColumnTransformer
  ├── StandardScaler       (age, bmi, children)
  └── OrdinalEncoder       (sex, smoker, region)
        │
        ▼
GradientBoostingRegressor
        │
        ▼
Predicted Annual Charge (float)
```

### Training Process

1. Load and inspect the dataset.
2. Remove duplicate rows.
3. Build the `ColumnTransformer` preprocessing step.
4. Wrap each candidate algorithm in a `sklearn.pipeline.Pipeline` (preprocessor → model).
5. Fit each pipeline on the identical training set.
6. Evaluate all five pipelines on the held-out test set using MAE, RMSE, and R².
7. Run 5-fold cross-validation (`KFold`, `random_state=42`) to confirm generalisation.
8. Select the model with the highest test R².
9. Persist the winning pipeline with `joblib.dump` (compression level 3).
10. Save all metrics and feature importances to `evaluation_results.json`.

## Algorithms Used

Five regression algorithms were trained and compared on the identical 80/20 split:

| Algorithm | Notes |
|---|---|
| Linear Regression | Baseline OLS model |
| Ridge Regression | L2-regularised linear model (`alpha=10.0`) |
| Lasso Regression | L1-regularised linear model (`alpha=1.0`, `max_iter=10000`) |
| Random Forest Regressor | 300 trees, `min_samples_leaf=2`, `random_state=42` |
| **Gradient Boosting Regressor** ✅ | 300 estimators, `learning_rate=0.05`, `max_depth=4`, `subsample=0.8`, `random_state=42` — **selected** |

## How Healthcare Cost Prediction Works

1. **User fills the form** with six inputs: Age, Biological Sex, BMI, Number of Children, Smoking Status, and US Region.
2. **Client-side validation** catches out-of-range or missing values immediately in the browser.
3. **POST /api/predict** sends a JSON payload to the Flask backend.
4. **Backend validation** re-validates all fields and returns HTTP 422 with per-field error messages if any input is invalid.
5. **The trained sklearn Pipeline** transforms the input row:
   - `StandardScaler` normalises `age`, `bmi`, `children`.
   - `OrdinalEncoder` converts `sex`, `smoker`, `region` to integers using the fixed category mapping fitted during training.
6. **GradientBoostingRegressor.predict()** returns the estimated annual charge.
7. **Risk classification** is applied to the raw prediction:

   | Predicted Cost | Risk Category |
   |---|---|
   | < ₹5,000 | Low |
   | ₹5,000 – ₹14,999 | Moderate |
   | ₹15,000 – ₹29,999 | High |
   | ≥ ₹30,000 | Very High |

8. **The result card** is rendered in the browser with the annual estimate, monthly breakdown, risk ribbon, and a profile summary chip grid.

## Limitations

- **Dataset scope** — the model is trained on a US insurance dataset. Cost patterns, regional factors, and demographic distributions may differ significantly in other countries, including India, where the INR display is used.
- **Static model** — the trained model is not updated automatically when new data becomes available. Retraining requires running `model/train_pipeline.py` manually.
- **Prediction range** — only a point estimate is returned; no uncertainty quantification is provided.
- **Six input features** — clinical factors such as pre-existing conditions, hereditary diseases, and healthcare utilisation history are not captured in this dataset and are therefore not accounted for.
- **Linear assumptions in tree splits** — while Gradient Boosting handles non-linearity well, extreme out-of-distribution inputs (e.g., BMI > 53) may produce less reliable predictions.
- **External CDN dependency** — the frontend loads Chart.js and Google Fonts from CDN. An internet connection is required on first load unless assets are served locally.

## Conclusion

MediCost AI demonstrates a complete, production-structured machine learning pipeline — from raw data inspection and preprocessing to model selection, serialisation, REST API deployment, and a fully connected browser-based user interface.

The selected **Gradient Boosting Regressor** achieves **89.36 % R²** on the held-out test set with a **mean absolute error of ₹2,571.67**, outperforming all four baseline algorithms evaluated in the same experimental setup. The dominant predictor is smoking status (61.82 % feature importance), followed by BMI (21.19 %) and age (13.28 %) — findings that are consistent with established healthcare cost research.

The application is self-contained, requires a single startup command, and serves both the REST API and the frontend from the same Flask process. All displayed statistics, metrics, and predictions are fetched live from the backend; no values are hardcoded in the interface.
